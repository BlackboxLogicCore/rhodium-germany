# Rhodium Germany — Global Bidding Table

## Purpose

The Global Bidding Table is the qualification and licensing framework for strategic Rhodium Worker-Box partners.

It does not transfer ownership of Rhodium Germany, the protected core, research systems, signing authority or future core development.

## License dimensions

Every license is defined across three axes:

### A. Territory
Country, region or another explicitly defined geographic scope.

### B. Field of use
Examples:

- Telecommunications / ISP / CDN
- Cloud / Data Center
- Finance / Banking / Payments
- Industry / Robotics / Logistics
- Embedded / OEM / Devices
- Automotive / Mobility
- Business Software / SaaS / Commerce
- Consumer
- Research
- Healthcare / MedTech
- Aerospace / Satellites

### C. Technical deployment scope
Examples:

- Server-to-server
- Server-to-client
- Transaction path
- Protected endpoint
- Device fleet
- Embedded/OEM unit
- Application class
- Data pipeline

A license does not automatically extend outside its agreed axes.

## Qualification sequence

### Stage 1 — Qualification
The candidate provides sufficient non-confidential information to establish:

- legal entity and operating territory
- intended field of use
- intended technical scope
- distribution/customer access
- technical integration capacity
- support capability
- sector-specific compliance capability
- commercial capacity appropriate to the requested rights

### Stage 2 — Black-Box Proof Package
Qualified candidates receive the permitted proof material for the requested scope.

No protected core source code is disclosed.

### Stage 3 — Controlled Qualification
The intended deployment, interfaces, acceptance matrix, responsibilities, evidence requirements and production boundary are defined.

This stage is not an unrestricted production license.

### Stage 4 — Commercial Bid
The bid can contain:

- requested territory
- requested field of use
- requested technical scope
- exclusivity request
- proposed upfront license fee
- annual minimum guarantee
- proposed usage metric
- deployment milestones
- support obligations
- contract duration

### Stage 5 — License Agreement
Only the signed agreement defines the granted rights.

### Stage 6 — Production Acceptance
Production deployment follows the agreed acceptance process and any mandatory external approvals.

## Exclusivity

Exclusivity is conditional, not permanent by default.

It can be tied to:

- minimum annual commercial commitments
- minimum deployment milestones
- market coverage
- support/service levels
- compliance obligations
- reporting obligations
- payment performance

Failure to meet agreed milestones can reduce, suspend or terminate exclusivity according to the final contract.

## Commercial model

The default model can combine:

1. **Upfront license / exclusivity fee**
2. **Annual minimum guarantee**
3. **Usage-based variable fee**
4. **Optional value-share** where the generated economic value is objectively measurable under an agreed method

Rhodium Germany should not depend solely on a licensee's self-reported net profit.

## Small and large partners

The framework is designed for more than global corporations.

Possible partner levels include:

- national strategic operator
- regional operator
- sector specialist
- OEM / embedded licensee
- systems integrator
- channel / reseller partner
- SME-focused operator

The commercial and technical scope should match the partner's real ability to operate it.

## Protected core

The following remain with Rhodium Germany:

- protected core implementation
- research systems
- Mother/release environment
- signing authority
- private keys and secrets
- internal research logic
- future core development

A licensee receives only the Worker-Box functions and interfaces authorized by the final agreement.

## Continuity

Critical deployments should not rely on an unsafe surprise shutdown.

Where authorization leases are used, the production design should define:

- renewal windows
- grace periods
- non-destructive fallback
- continuity procedures
- customer-data protection
- behavior after expiry or termination

## Unknown / latent defects

No software system can responsibly be represented as guaranteed universally error-free.

A Rhodium PASS applies to the defined tested criteria and scope. Before production, the licensee must complete the agreed acceptance process for its environment.

High-risk sectors can require additional independent review, certification, penetration testing, safety validation, insurance, regulator approval, fallback systems and formal change control.
